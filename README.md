# Достижения лицея — платформа ученических достижений

Ученик сам заявляет достижение (категория, название, дата, баллы), организатор проверяет —
и баллы сразу идут в рейтинг лицея и класса. Олимпиады по физике, математике и информатике
идут отдельной афишей: подтверждённое участие автоматически становится достижением.

Данные хранятся в SQLite на сервере, пароли — хешем `scrypt`. Сервер поднимается вместе
с Vite: отдельный процесс держать не нужно.

## Быстрый старт

```bash
npm install
npm run dev      # http://localhost:5173 (Vite + API на node:sqlite)
```

Проверка перед защитой:

```bash
npm run build    # tsc -b && vite build
npm run preview  # production-сборка вместе с API
npm run lint     # oxlint
npm run smoke    # 22 проверки API на отдельной базе
```

Нужен Node.js 22.5+ — используется встроенный модуль `node:sqlite` (проверено на 24.19.0).
Внешних зависимостей у сервера нет.

База создаётся сама в `data/hackathon.db` при первом запуске и наполняется демо-данными.
Путь можно переопределить переменной `HACKATHON_DB`.

## Что умеет

### Ученик
- Регистрация и вход по имени, классу и паролю; пароль хранится только хешем.
- Кабинет: сумма подтверждённых баллов, место в лицее и в классе, счётчик проверки.
- Список своих достижений с категорией, датой, статусом и комментарием организатора.
- Добавление достижения: категория, название, дата (не в будущем), баллы 0–500.
- Отзыв своей заявки, пока она на проверке.
- Афиша олимпиад: поиск, фильтр по статусу и направлению, запись на конкурс.
- Рейтинг лицея и классов: подиум, таблица, подсветка своей строки.

### Организатор
- Очередь достижений на проверке: уточнение баллов, комментарий, подтверждение или отклонение.
- Добавление достижения любому ученику от себя — сразу подтверждённое.
- Создание, редактирование и удаление конкурсов с валидацией дат и максимума баллов.
- Импорт достижений из CSV/JSON: предпросмотр ничего не пишет в базу, подтверждение — пишет.
- Отчёт CSV (`;`, BOM, CRLF) — открывается в Excel двойным щелчком.
- Сброс демо к исходному состоянию.

### Живая синхронизация
Вкладки обмениваются сигналом через `BroadcastChannel` и заново забирают данные с сервера.
Организатор подтвердил достижение — у ученика во второй вкладке обновились баллы, место
и сработала анимация числа (отключается при `prefers-reduced-motion`).

## API

Все запросы — `/api/*`, сессия в httpOnly-куке `hackathon_session` (SameSite=Lax, 7 дней).

| Метод | Путь | Кто может | Что делает |
| --- | --- | --- | --- |
| POST | `/auth/register` | все | регистрация: имя, класс, пароль, роль |
| POST | `/auth/login` | все | вход по имени, классу и паролю |
| POST | `/auth/demo-login` | все | быстрый вход по id (можно выключить: `HACKATHON_DEMO_LOGIN=0`) |
| GET | `/auth/demo-accounts` | все | список демо-аккаунтов |
| GET | `/auth/me` | все | текущий пользователь |
| GET | `/users` | все | список учеников и организаторов |
| GET | `/achievements?studentId&status` | ученик — свои, учитель — все | достижения |
| POST | `/achievements` | ученик и учитель | ученик создаёт `pending`, учитель может сразу `approved` |
| PATCH | `/achievements/:id` | учитель | верификация: статус, комментарий, уточнение баллов |
| DELETE | `/achievements/:id` | ученик — своё `pending`, учитель — любое | удаление |
| GET/POST | `/competitions` | все / учитель | афиша и создание конкурса |
| PATCH | `/competitions/:id` | учитель | правка конкурса |
| GET/POST | `/participations` | ученик — свои, учитель — все | заявки на конкурсы |
| PATCH | `/participations/:id` | учитель | подтверждение; создаёт достижение «олимпиада» |
| POST | `/demo/reset` | учитель | сброс к демо-состоянию |

### Импорт достижений
CSV (разделитель `,` или `;`, кавычки поддерживаются) или JSON-массив:

| Колонка | Обязательна | Синонимы |
| --- | --- | --- |
| `student` | да | `ученик`, `фио`, `name` |
| `grade` | нет | `класс` — уточняет однофамильцев |
| `category` | да | `категория`: `academic`, `olympiad`, `project`, `volunteer` |
| `title` | да | `название`, `достижение` |
| `points` | нет | `баллы`, `балл` (0–500) |
| `date` | нет | `дата`, `awardedOn` |

Строка отклоняется с понятной причиной: пустая, не хватает полей, ученик не найден,
неизвестная категория, баллы вне диапазона, дата не в формате `ГГГГ-ММ-ДД`, дубликат.

### Отчёт
`Ученик;Класс;Категория;Достижение;Баллы;Статус;Источник;Дата` — UTF-8 с BOM, `;`, CRLF.

## Архитектура

```
server/        db.js (node:sqlite и схема), api.js (роуты и валидация), seed.js, password.js (scrypt)
               vite-plugin.js (монтирует API в dev и preview), smoke.mjs (проверка API)
src/
  data/        типы, HTTP-клиент api.ts, категории, импорт/экспорт, SVG-дипломы
  lib/         рейтинг учеников и классов, хуки анимации
  state/       store.tsx — единый StoreProvider (сессия + данные + синхронизация вкладок)
  pages/       Login, Poster, Competition, Cabinet, Rating, Admin
  components/  Header, ImportPanel/ReportPanel
  styles/      tokens, layout, components, poster, admin, cabinet, motion
```

- Страницы не знают про HTTP: всё общение идёт через `api.ts` и `useStore()`.
- Валидация дублируется осознанно: на клиенте — быстрый отклик, на сервере — защита.
- Уникальность аккаунта — пара «имя + класс» (`login_key`), поэтому однофамильцы не конфликтуют.
- Верификация конкурсной заявки создаёт достижение с `source='contest'` идемпотентно
  (повторное подтверждение не дублирует баллы).
- Превью афиши — SVG в `public/poster-*.svg` с CSS-анимацией внутри, уважающей `prefers-reduced-motion`.

## Технологии

Vite 8, React 19, TypeScript 6, React Router 7, CSS без UI-библиотек, oxlint.
Сервер — Node.js без фреймворков: `node:http`, `node:sqlite`, `node:crypto`.
Шрифты — системные: Georgia (заголовки) и Manrope с фолбэком на Segoe UI (текст).

## Дизайн

«Школьный стенд достижений»: чернильный хвойный `#1E4D45`, тёплый янтарь, бумажный фон `#F4F2ED`.
Восьмипиксельная сетка, радиусы 8/12/999, тени только для иерархии, контраст текста не ниже 4.5:1.
Анимации — только для обратной связи (появление, изменение числа), 120–520 мс, с уважением к `prefers-reduced-motion`.

## Ограничения прототипа

- Сессия в куке, а не JWT: для одного сервера этого достаточно, для кластера нужен общий store.
- Быстрый демо-вход включён по умолчанию — на проде его надо выключить (`HACKATHON_DEMO_LOGIN=0`).
- Дипломы — SVG, не PDF (осознанно: без внешних зависимостей).
- Импорт не поддерживает Excel-файлы напрямую — только CSV/JSON.
- Сброс демо возвращает всех к исходным данным — это общая база, не личная копия в браузере.
